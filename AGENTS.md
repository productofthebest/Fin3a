- AI assistant streams from `src/routes/api/chat.ts` (server route, bearer-verified) using the user's own OPENAI_API_KEY; the model only receives aggregate totals from `assistant-context.server.ts`, never descriptions/notes — keeps personal data minimal.
- Phone sign-in is a custom server OTP (`phone-otp.server.ts`, rules in `phone-otp.ts`) delivered by Termii because Cloud Auth's SMS can't use Termii; codes are HMAC-hashed in `phone_otps` (service-role only), phone→account mapping lives in `phone_identities`, and verified codes mint a Cloud Auth session via an admin magic-link token so email/Google/Lovable accounts stay untouched. Never link a phone without a verified code. Shared auth validation lives in `auth-options.ts` and field controls in `auth-fields.tsx`.
- Use `page-meta.ts`; size accounts from composer/Split Bill, no inner scroll. Bills retains recurring tracking; no provider payments before funded sandbox verification.
- Use `record-currencies.ts` for currency choices/row formatting and `financial-calculations.ts` for separate currency totals; assistant snapshots carry `byCurrency` to avoid hiding USD behind NGN preferences. Unknown-currency/review rows stay excluded; cash flow is not balance. Historical averages exclude first/current partial months and disclose UTC/coverage assumptions.
- Historical comparison arithmetic lives in `financial-analysis.ts`; shared stable pagination retrieves all owned financial rows for dashboard, analysis and assistant totals. `planning-calculations.ts` handles scenarios, affordability, goals and evidence; protected planning functions persist dated currency-specific confirmations and scenario inputs, then recalculate server-side. Client-only what-if stays an ephemeral preview, never a balance or scenario authority. Forecasts need a confirmed balance plus three complete historical months.
- Planning schema types extend locally in `planning-types.ts` until managed types regenerate; generated integration files stay untouched. Saved features require the staged migrations — never verify against missing schema or fake fallback rows.
- Scanner imports require explicit currency/classification review; the database RPC serializes per-user imports, preserves immutable user-scoped transaction identity and atomically tracks imported draft IDs. Content hashes identify original files; review flags are candidates, never automatic deletions.
- Synthetic finance fixtures live only under `src/test/fixtures` (test-runner-only); application modules and migrations never import or seed them. Backend fixture tests must verify an isolated nonproduction backend before creating accounts or records, and test rows must never be staged or merged.
- Document vision extraction uses `document-openai.server.ts` through the authenticated scanner handler with the existing OpenAI secret, direct Responses API and storage disabled; no gateway fallback or raw provider errors prevent unintended billing and sensitive-data exposure.
- Account-agnostic query keys require synchronous cache clearing and query cancellation on logout or identity changes through `session-cache.ts`, preventing the previous account's cached financial workspace from rendering.
- Document registration and extraction share `document-security.ts` for size/type, account-prefix and actual-byte validation; storage deletion errors must preserve the document row so private-file cleanup can be retried.

- Personal AI endpoints (`/api/landing-chat`, `/api/transcribe`, `/api/chat`) require a verified bearer; guest text uses `/api/public/guest-chat` with no financial reads and a separate service-role-only atomic admission ledger, because public access must not impersonate an account or bypass quotas. Homepage model input accepts only the latest user question, not browser-authored assistant history.
- Statement reconciliation and duplicate matching are pure functions in `statement-reconciliation.ts` (integer cents, printed figures only); PDFs are split with pdf-lib so long statements fit model limits and a failed part fails the whole scan.
- Account OpenAI calls go through `beginAiUsage`/`finishAiUsage` (DB `ai_begin`/`ai_finish`); guest calls use `ai_guest_begin`/`ai_guest_finish` with conservative reservations, fixed guest caps and verified model prices independent of unset account pricing. Both honor the shared kill switch; guest errors retain unknown-cost reservations. Admin RPCs re-check `has_role('admin')` in the database. Guest admission does not repair the pre-existing concurrency gap in account admission.
- Web research runs separately: Dashboard and homepage use the shared bounded public-question validator with conservative sensitive-input rejection and own-record questions excluded. Never supply stored identity, history or financial snapshots to research; final personal answers have no search tool. `ai_web_reserve`/`ai_web_finish` retain bounded fee reservations on unknown outcomes; HTTPS sources are validated. Input detection is not guaranteed anonymisation, and legacy account-budget concurrency remains uncertified.
- Accounts: NGN/USD balances derive from verified `account_ledger` entries via `computeAccountBalance` — never increment on request creation; no crypto until Breet is configured, fakes forbidden. P2P money moves via security-definer `execute_internal_transfer` (row lock, balance check, idempotency, paired ledger), returning status so failed attempts persist. Split RLS uses `is_split_participant`; money/QR actions rate-limited via `consume_rate_limit`; split math is integer cents in `src/lib/split-bill.ts`. QR codes encode opaque URLs; requests are single-use rows in `qr_payment_requests` paid via `pay_qr_request`; scans log to `qr_scan_events`.
- Admin uses AdminShell and existing authorized AI RPCs; presentation must not widen roles or financial reads. Unverified financial administration stays unavailable.
